本模块位于 application 层，由四个职责单一的服务组成：
- ReviewIntakeService：负责 Markdown 需求文件的校验、解析与不可变 RequirementSnapshot 的创建，通过 IntakeKey（提交者+仓库路径+分支+commit+内容哈希）实现进程内去重，并在 persistenceEnabled 时通过 ReviewPersistenceMapper 双写根记录；同时维护 submissions 缓存以支持幂等回放。
- ReviewOrchestrationService：编排 Director 规划与四核心角色（PRODUCT/PROJECT/FRONTEND/BACKEND）及 JUDGE 的注册与激活，使用 AgentRuntimeAdapter 启动会话、按 parallelRoleRounds 并发派发角色轮次，并通过 ReviewStateMachine 驱动 Review 聚合的状态迁移；计划修订受 maxPlanRevisions 限制，所有编排事件经 ReviewEventPublisher 发布为领域事件。
- ReviewLifecycleService：在安全边界上执行 cancel/retry 命令，依赖 ReviewStateMachine 做状态转换，通过 ReviewDebateStore 阻止已有人工最终决策后的取消，并使用 RetryKey 对重试结果做进程内幂等缓存。
- ReviewRecoveryService：在进程重启后根据 Review.roleActivations 重新 attach 到稳定的 AgentScope director/role session，先尝试 resume，失败则 start + registerRole 重建句柄。
依赖方向严格自顶向下：application → domain（Review、ReviewStateMachine、ReviewRegistry、ReviewDebateStore）→ infrastructure（AgentScope 适配层、Markdown 解析、MyBatis Mapper），不反向依赖基础设施。
