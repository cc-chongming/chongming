- 构造器参数统一使用 Objects.requireNonNull 进行非空校验，并在异常消息中携带参数名（如 "xxx must not null"）。
- 对外部输入采用 try-catch 宽容解析策略：JSON 解析失败时降级为 fallback（如截断摘要或空列表），保证服务可用性。
- 文件系统操作一律先通过 verifyWorkspacePath / RepositoryBoundaryGuard 校验路径未逃逸工作区或仓库白名单，再执行读写。
- 关键持久化（snapshot reference、manifest、metadata）采用临时文件 + 原子 move（ATOMIC_MOVE）写入，失败时 finally 中清理临时文件。
- 长耗时 I/O 过程中持续检查 IntakeCancellation.checkCancelled()，支持取消流程。
- 并发安全通过 per-key Object 锁（ConcurrentMap.computeIfAbsent）保护共享快照创建与清理，避免竞态。
