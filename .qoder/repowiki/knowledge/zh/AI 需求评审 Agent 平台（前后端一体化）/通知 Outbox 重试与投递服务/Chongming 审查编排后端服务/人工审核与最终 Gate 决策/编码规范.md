- 领域模型使用 Java record 并在校验块中拒绝非法参数（非空、长度上限、枚举值、版本顺序），保证构造即合法。
- 写操作采用乐观锁：更新/删除方法接收 expectedVersion，并在领域对象内部比对 version 后生成新版本记录。
- 应用服务通过构造函数注入所有依赖并使用 Objects.requireNonNull 做防御式检查，同时暴露带 Clock 参数的包可见构造以便测试。
- 控制器内定义局部 record（DraftRequest、FinalDecisionRequest）将 HTTP 入参转换为领域命令或 DraftContent，再委托给 Service。
- 所有写路径在持久化后追加 HumanReviewAuditEvent 并通过 ReviewEventPublisher.publish 发布 ReviewEventType，保持审计与事件双写。
- 读接口提供基于 ReviewId 的重载方法以支持重启后未注册 Review 时的只读查询，写接口则要求 Review 聚合已注册。
