本模块位于 application 层（AssessmentService、ReviewDispatchService）与 domain model 层（ReviewAssessment、ReviewDispatchCommand），遵循分层架构：application 服务通过 domain/repository 接口（ReviewAssessmentStore、ReviewDispatchStore、ReviewDebateStore）访问仓储，不直接依赖基础设施实现；domain model 为不可变 record，仅包含状态与不变量校验，不持有仓储引用。
- AssessmentService：接收角色提交的 checkpoint 评估，注入 review/attempt/role/version/idempotencyKey 等服务器端身份后落库，并通过 RolePackRegistry + checklist 计算缺失必填检查点，提供 isCoverageComplete / derivedCompletionSummary 完成守卫能力。
- ReviewDispatchService：将 Director 的调度决策冻结为可验证的 ReviewDispatchCommand 信封，按 PENDING→CONSUMED|EXPIRED|REJECTED 严格生命周期推进；issue/resolved/consume/rejectAllPending 均使用 synchronized(review) 保证同一 Review 聚合内的并发安全；事件发布通过 ObjectProvider<ReviewEventPublisher> 懒解析以避免与 ReviewEventService 的循环依赖。
- ReviewAssessment：以 checkpointKey 作为稳定键，status.requiresReasonSummary() 控制 reasonSummary 必填性，storageKey = roleType:checkpointKey 用于幂等覆盖。
- ReviewDispatchCommand：封装 allowedAction（CHALLENGE/REBUTTAL/POSITION_CHANGE/EVIDENCE_REQUEST）、目标 topic/claim/turn、过期时间，withStatus 强制单向状态迁移，isExpiredAt 驱动过期转换。
