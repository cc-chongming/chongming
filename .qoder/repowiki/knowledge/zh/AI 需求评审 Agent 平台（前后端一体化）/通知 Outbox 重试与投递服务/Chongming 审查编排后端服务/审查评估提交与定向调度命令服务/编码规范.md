- 领域模型使用 Java record 并在校验器中拒绝非法参数，所有字段在构造时即满足不变量，状态变更通过 withStatus 返回新实例而非原地修改。
- 应用服务方法入口对关键参数执行 Objects.requireNonNull 校验，并在 synchronized(review) 块内执行业务逻辑以保证同一 Review 聚合的并发安全。
- 对外暴露的输入边界使用内部 record（AssessmentSubmission、DispatchProposal）承载强类型入参，由构造函数完成非空与格式校验，原始模型输出不直接写入仓储。
- 幂等性通过 idempotencyKey 实现：提交前查询 Review.commandResults 或 dispatchStore.findByIdempotencyKey，命中则直接返回已存储结果并标记 replayed=true。
- 权限与角色校验集中放在私有方法（validateReviewAndRole、requireCheckpointOwnership、validateProposal），依据 Review.roleActivations 与 RolePack.checklist 判断是否允许操作。
- 领域异常统一通过 ReviewDomainException(ReviewErrorCode, message) 抛出，错误码语义化区分 REVIEW_ID_MISMATCH、ILLEGAL_STATE_TRANSITION、UNAUTHORIZED_ROLE、DISPATCH_COMMAND_EXPIRED 等场景。
