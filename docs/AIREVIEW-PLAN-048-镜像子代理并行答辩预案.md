# AIREVIEW-PLAN-048 镜像子代理并行答辩（预留预案，未实施）

> **状态**: ⏸️ 预留预案（2026-08-27 用户决策：现阶段采用方案 A——角色单实例、议题间串行；本计划仅作为未来演进预案存档）
> **创建日期**: 2026-08-27
> **目标**: 存档“多议题并行答辩”的两个演进方向（B 镜像并行 / C 并行推理+串行提交），记录启用条件与风险，供议题规模增长时决策。

## 背景与决策记录

- 问题：PLAN-047 后议题生命周期独立，但每个角色在一次评审中只有一个 agent 实例（`registerRole` 按角色单会话），派发信封在角色会话内排队——同一角色跨议题的答辩/质询**串行**执行（证据：评审 48277fac 产品经理 4 条答辩串行落库，间隔 15~45 秒）。不同角色之间本就并行。
- 决策（用户，2026-08-27）：**选 A（维持现状）**。理由：评审价值在答辩质量与立场一致性——同一角色跨议题的立场需要互相知情、自洽；镜像并行会派生互不知情的“角色镜像”，存在跨议题立场矛盾风险；当前议题数下串行时延（分钟级）可接受。

## 预案 B：(角色×议题) 镜像子代理并行

- 做法：派发时按 (角色, 议题) 派生镜像会话，各镜像在自己议题下并行执行答辩/质询。
- 收益：真并行，墙钟时延 ≈ 单议题时延。
- 风险：跨议题立场矛盾（两个“产品经理镜像”互不知情）；同角色并发写的聚合版本冲突（expectedVersion 乐观锁重试放大）；审计归属复杂（同一角色多会话来源）；镜像会话生命周期与成本。
- 缓解方向：镜像以该角色已落库 Claim + 议题上下文为种子；写冲突走版本重试。

## 预案 C（推荐演进路径）：并行推理 + 角色级串行提交

- 做法：(角色×议题) 镜像并行**推理**（耗时大头），写动作（submit_claim/质询回合/立场变更）经角色级串行提交队列落库。
- 收益：并行收益保留，提交一致性受保护，审计链单一。
- 成本：运行适配器需支持镜像会话与写队列，规模不小于 PLAN-047。

## 启用条件（建议）

- 单次评审议题数持续 > 10，或单角色串行链墙钟时延成为使用痛点；
- 前置：PLAN-047 议题独立化已落地（议题级生命周期是镜像并行的前提）；
- 演进顺序：先 C 后 B（C 保住一致性底线）；任何方案落地前先做一次“跨议题立场一致性”的评测设计。
