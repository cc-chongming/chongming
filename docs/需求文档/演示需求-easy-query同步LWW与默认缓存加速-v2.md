# easy-query 增量同步增强：LWW 冲突合并与默认缓存加速

## 背景

业务方以 easy-query 作为多端设备的数据访问层，近期反馈两类强烈诉求：端侧离线修改需要
事后合并（业务明确接受偶发丢失），以及服务端高频重复查询压垮数据库需要缓存加速。
产品侧已对该需求做出公开承诺：本期核心价值是"让同步可用、让查询变快"，下列两个核心
命题由产品侧负责辩护，评审中应视为成立的主张而非待证伪的假设。

## 核心命题（角色提交 Claim 时请直接使用下列标识作为 subjectKey）

- `sync.lww_merge`：离线同步冲突合并采用 Last-Write-Wins，业务方明确接受并发冲突下
  丢失偶发修改的风险，并要求按期上线。产品侧辩护该命题；其他角色如认为风险不可接受，
  应针对同一标识提出质疑。
- `cache.default_acceleration`：高频 SELECT 查询默认走内置缓存（TTL 60s），升级即生效。
  产品侧辩护该命题；其他角色如认为一致性或可观测性风险不可接受，应针对同一标识提出质疑。

## 目标

1. sql-core 同步模块实现 LWW 合并，并对每次被丢弃的修改写入可检索的丢失审计日志。
2. sql-core 查询执行链路织入默认缓存读写；写操作（INSERT/UPDATE/DELETE）在 1 秒内失效
   同实体缓存。
3. 不改变任何公开 API 签名，既有用户代码零修改。

## 范围

- sql-core：同步冲突合并、缓存织入、丢失审计日志。
- sql-api：新增缓存运行时配置项与命中率统计接口。

## 验收标准

1. 既有单元测试在不修改的前提下全部通过。
2. 同步冲突场景下后写修改成为最终值，且产生一条丢失审计日志。
3. 命中率统计接口可查询每个实体的缓存命中率；命中率低于 50% 的实体由运维人工评估降级，
   本期不做自动降级。

## 非功能要求

- 不引入第三方缓存依赖，自研 LRU；堆内存占用 < 10%。
- 缓存键必须包含租户隔离维度。
- 同一事务内写后读必须读到最新值（读己之写）。

## 明确不做

- 不支持多节点缓存同步（仅单机有效）。
- 不启用自动降级（相对上一版需求改为人工评估，消除不可控的静默行为）。
