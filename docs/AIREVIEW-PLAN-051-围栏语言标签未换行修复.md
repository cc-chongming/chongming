## 背景

- 用户批注：模型输出 ```json{（围栏语言标签后直接跟 `{` 未换行）时，渲染后 `{` 消失。
- 现状勘察（`frontend/src/services/safe-markdown.js` 约 61-72 行）：围栏解析把反引号后的整段 `fence[2]` 作为 info 处理，`infoToken = fence[2].trim().split(/\s+/)[0].replace(/[^\w+#.-]/g, '')`——`json{` 清洗成 `json` 作为语言类，而 `{`（语言标签后的全部残留）直接丢弃，不进入代码块。
- 修在渲染侧而非提示词：确定性兜底，不赌模型输出换行的自觉。

## 分段方案

### 段 1：围栏 info 残留字符回补

**涉及文件**：修改 `frontend/src/services/safe-markdown.js`、`frontend/src/services/safe-markdown.test.js`

**关键实现细节**：
- 解析围栏行：语言标签取 `^[\w+#.-]+` 前缀（与现有清洗口径一致），标签之后的残留（去空白后）作为代码块**第一行**回补；
- 兼容两种形态：```json{（紧贴）与 ```json {（带空格）；也兼容 ```js console.log(1) 这类整行内联内容；
- 既有行为必须保持：语言前空格（``` json）、缩进围栏、加长围栏（````）、未闭合流式围栏、嵌套围栏（现有测试全绿）。

**测试新增**：
- ```json{ + 后续行 + 闭合 → `{` 为代码首行、语言类 language-json；
- ```json { 空格形态同样回补；
- 围栏行内联内容（```js console.log(1)）整体进代码块；
- 正常换行围栏不受影响（回归断言）。
