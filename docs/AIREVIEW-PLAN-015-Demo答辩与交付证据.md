# Demo、答辩与交付证据计划

> **状态**: ⏳ 待实施
> **创建日期**: 2026-07-14
> **目标**: 将完整系统固化为可重复演示、可故障恢复、可量化说明并能证明 AI-native 开发深度的比赛交付物。
> **前置计划**: PLAN-011 至 PLAN-014

## 0. 背景与边界

比赛交付不仅要“跑起来”，还要清楚呈现多 Agent 真实辩论、证据链、人工 Gate 和开发过程中的 Codex 使用深度。当前不承诺缓存结果作为断网
替代；现场故障只能展示明确标注的规则降级、已归档演示视频或错误恢复，不得冒充实时评审。

## 1. 分段方案

### 1.1 冻结演示场景 ⏳

- 主场景：包含前后端冲突、P1 风险、补证、立场变化和 Judge 的完整需求。
- 备用场景：更短、依赖更少，但仍能展示至少一次真实质询。
- 保存 Markdown、仓库 commit/manifest、Ground Truth、预期事件锚点和数据授权说明。

### 1.2 环境检查与初始化 ⏳

- 检查 Java 21、MySQL、端口、模型连接、学习通 MCP、目录权限和磁盘。
- 提供幂等数据库迁移、Demo 数据初始化和重置，不依赖手工删表。
- 配置样例仅有占位符；启动前提示缺失变量。

### 1.3 一键演示路径 ⏳

- 固定链路：创建 → Plan → 四角色立论 → 动态角色 → 冲突 → Challenge → Rebuttal/Position → Judge → 人审 CRUD → Gate → 通知。
- 每步定义 UI 锚点、讲解语句、预期事件、最长等待和超时处理。
- Demo profile 固定模型、Prompt、数据集和动画行为，不修改生产安全边界。

### 1.4 故障演练 ⏳

- 冷启动、模型超时、SSE 重连、通知失败、应用重启、MySQL 短断。
- 每个故障准备检测信号、现场话术、恢复步骤、允许继续/切备用场景条件。
- 不使用未决缓存结果伪装在线链路。

### 1.5 稳定性预演 ⏳

- 主场景从干净状态连续 5 次，备用场景 3 次。
- 记录总耗时、每阶段耗时、失败点、恢复时长和人工操作。
- 任一次失败必须形成根因/修复/复测记录，不能只重跑挑成功录像。

### 1.6 6～8 分钟答辩脚本 ⏳

- 1 分钟：问题与“替你判”定位；1 分钟：Harness 主持人和 Plan。
- 2～3 分钟：真实 Claim 驱动辩论与 Evidence；1 分钟：Judge/Gate/人工。
- 1 分钟：AgentScope 2.0/MySQL/恢复；1 分钟：评测和 AI 开发证据。
- 准备为什么多 Agent、为什么 Harness、如何防止自说自话、失败如何恢复等问答。

### 1.7 AI-native 开发证据 ⏳

- 每个 PLAN 保存 Codex 方案讨论、Prompt 迭代、生成 diff、人工修改、测试结果和审查结论。
- 按“任务 → AI 参与 → 人工判断 → 可验证产物”编目，不以产品内 Agent 数替代开发工具深度。
- 对敏感信息脱敏，保留 commit/计划/测试引用。

### 1.8 最终交付包 ⏳

- 技术方案、15 个计划、架构/时序图、API/事件样例、评测报告、安全/恢复报告。
- 演示视频、截图、主/备用脚本、环境清单、配置模板、数据库迁移、运行手册。
- 版本清单包含 commit、AgentScope、模型 profile、Prompt、dataset、MCP contract。

## 3. 实施顺序

1. **步骤 1**：第 4 周前选定候选场景，第 5 周冻结输入和 Ground Truth。
2. **步骤 2**：实现环境检查、初始化、重置和固定演示链。
3. **步骤 3**：执行故障演练，补运行手册和备用切换条件。
4. **步骤 4**：完成 5+3 次稳定性预演并清零阻断缺陷。
5. **步骤 5**：录制视频、定稿答辩脚本和问答。
6. **步骤 6**：汇总评测、版本和 Codex 开发证据，封存交付包。

## 4. 验证与退出标准

- 主场景 5/5、备用场景 3/3 从干净状态完成，演示不超时。
- 观众能在 UI 中看到至少一次 Claim → Challenge → Rebuttal/Position → Judge 完整链。
- Gate 可追溯到 Turn/Claim/Evidence，人工决定和通知有审计。
- 环境检查能在演示前发现所有必需依赖；每个预演故障有恢复步骤。
- 交付包从新环境按文档可复现，且不包含真实密钥/敏感数据。
- AI 工具应用深度证据以开发流程产物为主，引用具体计划、diff 和测试。

## 5. 风险与应对

| 风险        | 应对                                |
|-----------|-----------------------------------|
| 现场网络/模型异常 | 明确失败状态、规则降级和备用场景；缓存策略未决不冒充实时结果    |
| Demo 过长   | 每阶段设置硬时间预算，超时转人工/备用讲解             |
| 证据材料临时补录  | 从 PLAN-002 起持续归档，PLAN-015 只做索引和脱敏 |
